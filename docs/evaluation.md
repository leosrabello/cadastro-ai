## Measurements on synthetic documents

`backend/scripts/evaluate.py` builds a labelled synthetic set (known names, CPFs, dates, validity
and planted anomalies), degrades about half of the images (blur, JPEG quality 35–80, rotation up to
2°, 55% downscaling), runs the real pipeline, and writes `eval-report/report.json`.

Latest run: 60 cases, 63 documents, seed 7, Tesseract, AI off.

| Metric | Result |
| --- | --- |
| Field-level accuracy, overall | 98.6% |
| — name, birth date, issue date (RG), CEP | 100% |
| — CPF | 96.9% |
| — CNH expiry date | 94.4% |
| Validity decision accuracy (valid / expired / too old) | 98.2% |
| Planted anomalies detected: altered text layer, embedded instructions, editor metadata, name conflict | 12 of 12 (3 of each) |
| Integrity false alarms on clean cases | 0 of 48 |
| Registrations with a medium-or-higher finding needing a person | 48% (most are the deliberately expired or old documents in the set) |
| Processing time per document | 0.22 s mean, 0.26 s p95 (single page, local worker) |
| AI cost per document | not measured (AI off; no key in this environment) |

Remaining errors are all on degraded scans (rotation combined with blur or downscaling), where OCR
misses or misreads a date or digit. Those cases still end in a finding (missing expiry, check
digits invalid), not in a silent wrong answer.

**What these numbers are not.** They describe documents generated by this project with a clean,
regular layout. Real documents have photos, holograms, glare, phone-camera perspective, many
regional RG layouts and handwritten fields. The real accuracy will be lower, and the false-positive
rate of the integrity signals (ELA in particular) will be higher. No fraud-detection accuracy is
claimed. Confidence values are OCR or rule indicators, not calibrated probabilities.

## Measuring on real documents before go-live

1. Sample 300–500 historical registrations stratified by document type, channel (scan, phone
   photo, digital PDF) and state of issue. Anonymize or process inside the production security
   perimeter under the DPO's approval.
2. Two analysts label the fields, the validity decision and any known fraud cases independently;
   resolve disagreements. Keep the labels separate from the training of anything.
3. Run the pipeline over the set (adapt `evaluate.py` to read the labelled folder) with the
   candidate configuration: Tesseract, Azure, with and without AI.
4. Report per field and per document type: accuracy, fraction marked for review, false alarms per
   integrity signal, time and cost. Decide thresholds and provider from these numbers.
5. Repeat after any change to rules, providers or models.

## Measuring the reduction in manual work

The baseline must come from today's process: time 30–50 registrations end to end (minutes per
registration, documents opened, values typed or compared). After rollout the system records, per
registration, the time from first document to decision, the number of findings resolved by a
person, and the number of fields corrected (`GET /api/metrics`). Compare like with like (same mix
of PF/PJ and channels) over at least four weeks. Until that study is done, no reduction figure
should be quoted.
